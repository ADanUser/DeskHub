# Junior-вопросы по проекту и короткие ответы

## О проекте

### Что делает твой проект?

DeskHub — это Django-приложение для поиска и бронирования мест в коворкингах. Пользователь может выбрать город, найти коворкинг, отфильтровать свободные слоты, добавить слот в корзину и оформить бронирование.

### Почему выбрал Django?

Django подходит, потому что в нём уже есть ORM, миграции, шаблоны, авторизация, сессии и админка. Для проекта бронирования это позволяет быстро собрать полноценное web-приложение без написания всего с нуля.

### На какие части разделён проект?

На приложения `users`, `venues`, `bookings` и основную конфигурацию `deskhub`. `users` отвечает за пользователей, `venues` — за коворкинги и слоты, `bookings` — за корзину и бронирования.

## Django

### Что такое MVT?

MVT — это архитектурный паттерн Django:

- Model описывает данные;
- View обрабатывает запрос и возвращает ответ;
- Template отвечает за HTML-представление.

### Что такое view во Django?

View — это функция или класс, который принимает `request`, выполняет логику и возвращает `HttpResponse`, `render`, `redirect` или JSON.

### Что такое URL routing?

URL routing связывает путь запроса с конкретной view. Например, путь `/search/` связан с `venues.views.search`.

### Что делает `render()`?

`render()` берёт шаблон, context-данные и request, формирует HTML и возвращает HTTP-ответ.

### Что делает `redirect()`?

`redirect()` возвращает HTTP-ответ с перенаправлением на другой URL или named route.

### Что такое `get_object_or_404()`?

Это helper Django, который пытается получить объект из БД. Если объект не найден, возвращает HTTP 404.

## ORM и БД

### Что такое ORM?

ORM — это способ работать с базой данных через Python-классы и объекты, а не писать SQL вручную для каждого запроса.

### Какие связи используются в проекте?

Используются:

- `ForeignKey`: город → коворкинги, коворкинг → слоты, пользователь → бронирования;
- `OneToOneField`: один слот → одно бронирование.

### Чем `ForeignKey` отличается от `OneToOneField`?

`ForeignKey` — связь многие-к-одному: много объектов могут ссылаться на один. `OneToOneField` — связь один-к-одному: один объект может быть связан только с одним другим объектом.

### Что такое миграции?

Миграции — это файлы, которые описывают изменения структуры БД. Django применяет их командой `python manage.py migrate`.

### Что такое `select_related()`?

`select_related()` заранее загружает связанные объекты через SQL JOIN. Это уменьшает количество запросов к БД.

### Что такое N+1 query problem?

Это ситуация, когда сначала выполняется один запрос за списком объектов, а потом ещё по одному запросу для каждого связанного объекта. Например, 1 запрос за коворкингами и 100 запросов за городами.

## Транзакции и конкурентность

### Зачем в checkout используется `transaction.atomic()`?

Чтобы создание броней и изменение доступности слотов были одной атомарной операцией. Если произойдёт ошибка, все изменения откатятся.

### Зачем нужен `select_for_update()`?

Он блокирует выбранные строки БД до конца транзакции. Это нужно, чтобы два пользователя не смогли одновременно забронировать один слот.

### Как проект защищается от двойного бронирования?

Есть несколько уровней:

- при checkout проверяется `is_available`;
- строки слотов блокируются через `select_for_update()`;
- у `Booking` связь со `Slot` сделана через `OneToOneField`, поэтому один слот не может иметь две брони.

## Авторизация и сессии

### Как работает регистрация?

Пользователь отправляет форму `CustomUserCreationForm`. Если форма валидна, создаётся пользователь, выполняется `login()`, и пользователь перенаправляется на главную страницу.

### Что делает `@login_required`?

Он запрещает доступ неавторизованным пользователям. Если пользователь не вошёл, Django перенаправит его на страницу входа.

### Где хранится корзина?

Корзина хранится в сессии пользователя: `request.session['cart']`. В ней лежит список ID выбранных слотов.

### Почему корзина не в базе данных?

Потому что корзина — временное состояние. Для простого проекта сессии достаточно. Бронирование уже хранится в БД, потому что это постоянная бизнес-сущность.

## API

### Как реализовано API?

API реализовано обычными Django view-функциями, которые возвращают `JsonResponse`.

### Почему не использовал DRF?

API небольшое, поэтому Django `JsonResponse` достаточно. DRF имеет смысл подключать, когда API становится больше: нужны сериализаторы, ViewSet, permissions, token auth, OpenAPI.

### Какие API endpoints есть?

- `/api/venues/` — список коворкингов;
- `/api/venues/<id>/` — детали коворкинга и свободные слоты;
- `/api/bookings/` — бронирования текущего пользователя.

## Frontend

### Что используется на frontend?

Django Templates, Bootstrap 5, CSS и небольшой JavaScript для AJAX-добавления слота в корзину.

### Зачем AJAX?

Чтобы добавить или убрать слот из корзины без перезагрузки страницы и сразу обновить кнопку и бейдж корзины.

## Безопасность

### Где хранится SECRET_KEY?

В `.env`, а в `settings.py` читается через `os.getenv()`. Секреты нельзя хранить прямо в коде и коммитить в репозиторий.

### Как Django защищает формы?

Django использует CSRF-защиту. В проекте подключён `CsrfViewMiddleware`, а формы должны использовать `{% csrf_token %}`.

### Как пользователь не видит чужие бронирования?

Запросы фильтруются по текущему пользователю:

```python
Booking.objects.filter(user=request.user)
```

При отмене используется поиск по `id` и `user=request.user`, поэтому нельзя отменить чужую бронь.
